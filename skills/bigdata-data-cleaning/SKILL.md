# 大数据分析数据清洗与预处理工作流

本技能用于复用一套完整的大数据清洗与预处理流程。适合在用户已经完成数据采集，拥有 `data/raw/` 或 `data/interim/` 数据后，需要生成标准化分析数据、质量检查结果和清洗报告时使用。

## 一、总体流程

除非用户只要求完成其中某一步，否则按以下顺序推进：

1. 阅读数据采集方案、采集与质检报告、README 和现有字段说明。
2. 盘点输入数据文件、字段、行数、时间范围和数据粒度。
3. 编写《数据清洗与预处理方案》。
4. 设计清洗脚本，优先复用项目已有路径工具和目录结构。
5. 对每张输入表分别完成字段清理、类型转换、去重和缺失值处理。
6. 根据分析需要生成派生字段、聚合表和宽表特征。
7. 生成完整数据字典和质量摘要。
8. 运行脚本，检查输出文件、行数、空值和字段结构。
9. 编写《数据清洗与预处理报告》。
10. 整理运行命令、输出清单和人工审核说明。

不要直接覆盖原始采集结果。清洗输出应放入 `data/processed/` 或用户指定的派生数据目录。

## 二、输入数据盘点

清洗前先形成输入数据清单：

| 输入文件 | 数据内容 | 时间粒度 | 记录数 | 清洗重点 |
|---|---|---|---:|---|
| `data/interim/example.csv` | 示例数据 | 日/月/周 | 1000 | 日期、数值、类别、缺失值 |

重点检查：

| 检查项 | 说明 |
|---|---|
| 字段命名 | 是否使用英文 `snake_case` |
| 时间字段 | 是否存在年、月、周、日期等字段 |
| 数值字段 | 是否包含逗号、百分号、单位或异常符号 |
| 类别字段 | 是否存在同义写法、空格、脚注、别名 |
| 来源字段 | 是否保留 `source_url`、`raw_file`、`crawl_time` |
| 主键字段 | 是否能定义去重键 |
| 缺失字段 | 是真实缺测、源数据未提供，还是字段结构性不适用 |

## 三、清洗方案

在写脚本前先输出《数据清洗与预处理方案》。方案至少包括：

1. 项目主题和清洗目标。
2. 清洗原则。
3. 输入数据范围。
4. 通用清洗规则。
5. 各表字段标准化方案。
6. 缺失值处理策略。
7. 重复值处理策略。
8. 时间粒度对齐方案。
9. 输出表设计。
10. 质量控制方案。
11. 脚本设计和代码规范。
12. 阶段性实施计划。

推荐清洗规则：

| 清洗项 | 处理方式 |
|---|---|
| 文本空白 | 去除前后空格、换行、连续空白和全角空格 |
| 缺失值 | 将 `-`、`--`、`—`、`NA`、`N/A`、`null`、`None`、`nan` 标准化为空值 |
| 日期字段 | 统一为 `YYYY-MM-DD`、`YYYY-MM` 或 `YYYY-Www` |
| 数值字段 | 去除逗号、百分号和单位，转换为整数或小数 |
| 类别字段 | 建立标准映射表，统一同义写法 |
| 重复记录 | 按业务主键去重，记录删除数量 |
| 来源追溯 | 尽量保留来源链接、原始缓存路径和采集时间 |

## 四、代码架构

推荐目录结构：

```text
project/
├── data/
│   ├── interim/
│   └── processed/
├── logs/
├── src/
│   ├── cleaning/
│   │   ├── __init__.py
│   │   └── preprocess_data.py
│   └── utils/
└── 数据清洗与预处理报告.md
```

推荐模块划分：

| 模块或函数 | 职责 |
|---|---|
| `read_csv` / `write_csv` | 统一 CSV 读写编码和字段顺序 |
| `clean_text` | 统一文本空白和空值占位符 |
| `parse_int` / `parse_float` | 解析整数、小数、百分号和带单位文本 |
| `parse_date` | 标准化日期 |
| `normalize_*` | 标准化地区、类别、名称、指标 |
| `deduplicate` | 按业务主键去重 |
| `missing_count` | 统计字段空值 |
| `clean_<table>` | 每张表一个清洗函数 |
| `aggregate_*` | 时间粒度聚合，如日转周、日转月 |
| `build_features` | 构建分析宽表或特征表 |
| `build_dictionary_rows` | 生成数据字典 |
| `run_preprocess` | 串联完整清洗流程 |

代码规范要求：

1. 顶部写模块说明，说明输入、输出和设计原则。
2. 每个主要函数写 docstring。
3. 主流程按阶段注释。
4. 不把清洗逻辑散落在脚本底部，优先封装为函数。
5. 字段顺序固定，输出可复现。
6. 不用主观方式填补关键指标，除非用户明确要求并在报告中说明。

## 五、数据字典

清洗阶段必须生成完整数据字典，推荐文件：

```text
data/processed/data_dictionary.csv
```

字段建议：

| 字段 | 含义 |
|---|---|
| `table_name` | 字段所属清洗后数据表 |
| `field_name` | 字段名称 |
| `data_type` | 字段类型，如 string、integer、float、date、datetime |
| `unit` | 字段单位，无单位时填 `-` |
| `missing_value_strategy` | 缺失值处理方式 |
| `source_field` | 来源字段或派生字段来源 |
| `description` | 字段含义、统计口径和用途 |

数据字典应覆盖每张清洗后表的所有字段，而不是只写少量关键字段。

## 六、质量摘要

清洗阶段必须生成质量摘要，推荐文件：

```text
data/processed/quality_summary.json
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `input_rows` | 输入记录数 |
| `output_rows` | 输出记录数 |
| `duplicates_dropped` | 删除重复记录数 |
| `missing_cells_by_field` | 各字段空值数量 |
| `feature_columns` | 特征表字段数量 |
| `generated_at` | 清洗运行时间 |
| `output_dir` | 输出目录 |

空值解释要区分三类：

| 空值类型 | 示例 | 处理方式 |
|---|---|---|
| 源数据未提供 | 官方月报没有发病率 | 保留为空并说明原因 |
| 字段结构性不适用 | 排名记录没有阳性率 | 保留为空，不视为错误 |
| 真实缺测 | 气象 API 少量日期缺测 | 统计比例，后续分析时再决定插补或排除 |

## 七、清洗报告

清洗完成后输出《数据清洗与预处理报告》。建议包含：

1. 清洗概况。
2. 各阶段输入数据和输出数据。
3. 各表清洗处理说明。
4. 质量检查结果。
5. 空值产生原因解释。
6. 清洗后字段说明。
7. 数据字典和质量摘要说明。
8. 代码规范和可复现性检查。
9. 输出文件清单。
10. 后续分析建议。

字段说明表建议使用：

| 字段 | 含义 |
|---|---|
| `field_name` | 字段含义、单位、来源或计算方式 |

## 八、验证清洗结果

至少运行以下检查：

1. 脚本语法检查。
2. 完整运行清洗脚本。
3. 检查输出目录是否生成。
4. 检查输入行数和输出行数是否合理。
5. 检查重复记录数量。
6. 检查关键字段空值。
7. 检查数据字典是否覆盖全部输出字段。
8. 检查派生字段是否有明确来源。

常用命令：

```bash
python -m py_compile src/cleaning/preprocess_data.py
python src/cleaning/preprocess_data.py
```

如果输出 CSV 被 Excel、WPS 或预览程序打开，可能导致写入失败。提醒用户关闭相关文件后再运行。
