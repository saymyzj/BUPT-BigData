# 大数据分析数据可视化工作流

本技能用于复用一套完整的数据可视化流程。适合在用户已经完成数据采集、清洗和分析，并生成 `data/processed/` 与 `data/analysis/` 后，需要继续搭建交互式 Dashboard、整理图表说明、输出可视化报告和课程加分材料时使用。

## 零、承接上一位成员的结果

本技能默认承接成员 B 的数据清洗和数据分析成果继续工作。开始前必须先自动定位、读取并记录上一阶段交付物，不要重新采集或重复清洗数据，除非用户明确要求或发现关键输出缺失。

优先承接以下文件和目录：

| 上一阶段成果 | 默认位置 | 接续用途 |
|---|---|---|
| 清洗后数据 | `data/processed/` | Dashboard 明细数据、筛选项、股票列表、日期范围 |
| 分析结果 | `data/analysis/` | 趋势、相关性、异常检测、排名、聚类或风险分组图表 |
| 清洗数据字典 | `data/processed/data_dictionary.csv` | 字段含义、单位、缺失值策略、页面口径说明 |
| 分析数据字典 | `data/analysis/analysis_data_dictionary.csv` | 分析结果字段含义和图表说明 |
| 清洗报告 | `数据清洗与预处理报告.md` 或相近文件 | 报告中“数据来源与处理过程”引用 |
| 分析报告 | `数据分析报告.md` 或相近文件 | 图表解读和结论边界 |
| 运行日志 | `logs/` 或阶段报告中的命令记录 | 汇总三名成员 Agent 使用记录和运行日志 |

承接检查必须自动完成：

1. 检查 `data/processed/` 是否存在可读 CSV/JSON 文件。
2. 检查 `data/analysis/` 是否存在成员 B 的分析结果。
3. 识别时间字段、股票代码或股票名称字段、数值指标字段、类别字段。
4. 对每个候选输入文件记录行数、字段数、时间范围、股票数量和关键缺失字段。
5. 将可直接使用、需要转换、暂不可用的数据分别写入《数据可视化方案》。
6. 若上一位成员输出缺失，应在报告和日志中说明缺失项，并优先用已有清洗数据生成可视化，不得伪造分析结果。

## 一、主要职责与自动完成范围

除非用户限定范围，本技能需要自动完成并检测以下职责：

| 职责 | 自动完成内容 | 自动检测标准 |
|---|---|---|
| 基于成员 B 的清洗数据和分析结果搭建可视化页面 | 读取 `data/processed/` 和 `data/analysis/`，生成前端数据，搭建 Dashboard | 页面可运行，图表数据来自上一阶段输出 |
| 制作 3-5 种不同类型的图表 | 至少包含折线图、柱状图、散点图/热力图、饼图/环图、表格中的 3-5 类 | 图表数量和类型写入图表说明 |
| 实现交互功能 | 实现筛选、缩放、悬停提示、股票选择、日期范围选择、重置 | 每个交互都有可操作控件并影响对应图表 |
| 整理 Dashboard 页面截图和交互截图 | 保存首页、股票选择、日期范围、缩放、悬停提示等截图 | 截图路径写入报告，至少 1 张首页和 3 张交互截图 |
| 汇总三名成员材料 | 汇总 Agent 使用记录、Skills 文件、运行日志、输入输出样例 | 输出运行日志汇总和输入输出样例汇总 |
| 撰写报告可视化部分 | 写明图表设计、交互功能、数据口径、可视化结论 | 形成《数据可视化报告》或报告对应章节 |
| 撰写 AI 工具使用说明附录 | 汇总可视化 Agent 工作流、提示词、对话摘要、人工审核说明 | 形成 `Agent与Skill复用说明.md` 或报告附录 |

必须交付的成果：

1. 可视化 Dashboard 代码。
2. 可视化页面运行截图。
3. 交互功能截图。
4. 图表说明。
5. 运行日志汇总。
6. 输入输出样例汇总。

Agent / Skill 加分材料必须尽量补齐：

1. 可视化 Agent 工作流记录。
2. 可视化页面生成提示词或对话摘要。
3. Dashboard 运行命令截图。
4. 图表生成截图。
5. 交互功能截图。
6. 人工审核说明。

## 二、总体流程

除非用户只要求完成其中某一步，否则按以下顺序推进：

1. 阅读分工指南、数据采集报告、清洗报告、分析报告和数据字典。
2. 盘点 `data/processed/` 和 `data/analysis/` 中可用于可视化的数据表和字段。
3. 明确可视化主题、用户对象、展示目标和核心指标。
4. 编写《数据可视化方案》。
5. 设计 Dashboard 信息架构和图表组合。
6. 编写或更新前端数据准备脚本。
7. 生成前端可直接读取的数据文件。
8. 搭建 Dashboard 页面、样式和交互逻辑。
9. 实现筛选、指标切换、日期或周范围、缩放、悬停提示和重置功能。
10. 检查图表是否随筛选条件同步变化。
11. 编写《数据可视化报告》和 Agent/Skill 复用说明。
12. 启动本地服务验证页面，整理运行截图和交互截图。

不要只生成静态图片。应同时交付可运行页面、数据准备脚本、前端数据文件、图表说明和运行说明。

## 三、输入数据盘点

可视化前先形成输入数据清单：

| 输入文件 | 数据内容 | 可视化用途 |
|---|---|---|
| `data/processed/example_clean.csv` | 清洗后明细数据 | 趋势、分布、筛选 |
| `data/processed/features.csv` | 特征宽表 | 地图、散点、排名、KPI |
| `data/analysis/time_series_summary.csv` | 时间序列摘要 | 趋势卡片、变化提示 |
| `data/analysis/correlation_matrix.csv` | 相关性结果 | 热力图、相关性列表 |
| `data/analysis/cluster_results.csv` | 聚类或风险分组 | 风险地图、分布图、榜单 |
| `data/analysis/anomaly_detection_results.csv` | 异常检测结果 | 预警表、异常时间线 |
| `data/analysis/keyword_sentiment_analysis.csv` | 关键词或关注分析 | 关键词图、关注主题 |

重点检查：

| 检查项 | 说明 |
|---|---|
| 时间字段 | 是否有日期、月份、周次或年份，能否排序 |
| 空间字段 | 是否有省、市、区域、经纬度或分组 |
| 数值字段 | 是否能作为折线、柱状、散点、热力图指标 |
| 类别字段 | 是否能作为筛选器、颜色、分组或图例 |
| 结果字段 | 分析结果是否有风险等级、异常类型、相关性强度 |
| 数据口径 | 不同年份或数据源是否存在字段缺失或口径变化 |

如果某个字段只在部分年份存在，应在页面空状态和报告中说明，并提供可替代指标。

## 四、数据可视化方案

在写页面前，先输出《数据可视化方案》。方案至少包括：

1. 可视化目标。
2. 输入数据。
3. 图表类型和指标设计。
4. 交互功能设计。
5. 页面结构设计。
6. 数据准备脚本设计。
7. 运行方式。
8. 输出文件清单。
9. 截图计划。

图表通常至少覆盖 3-5 种类型：

| 图表类型 | 适合展示 |
|---|---|
| 折线图 | 时间序列趋势、最新值、峰值、变化趋势 |
| 柱状图 | 类别对比、地区对比、场景对比、风险等级分布 |
| 饼图或环图 | 构成比例、优势类别、最新周或最新月份结构 |
| 散点图 | 两个数值变量关系、气象与风险、规模与波动 |
| 地图或类地图网格 | 省市风险分布、地区排名、空间差异 |
| 热力图 | 相关性矩阵、指标强度、时间 × 类别密度 |
| 表格 | 异常候选、Top N 排名、人工复核清单 |
| 气泡图或词云 | 关键词关注、主题强度、舆情或官方文本关注点 |

## 五、Dashboard 代码架构

推荐目录结构：

```text
project/
├── data/
│   ├── processed/
│   ├── analysis/
│   └── dashboard-data.js
├── src/
│   └── dashboard/
│       ├── dashboard.html
│       ├── styles.css
│       ├── app.js
│       └── prepare_dashboard_data.py
├── 数据可视化方案.md
├── 数据可视化报告.md
└── Agent与Skill复用说明.md
```

推荐模块划分：

| 文件或函数 | 职责 |
|---|---|
| `prepare_dashboard_data.py` | 读取清洗和分析结果，生成前端数据 |
| `read_csv` | 统一读取 CSV |
| `to_float` / `to_int` | 数值转换 |
| `build_*_series` | 生成趋势、构成、风险、关键词等前端数据 |
| `dashboard.html` | 页面结构和图表容器 |
| `styles.css` | 页面视觉系统、响应式布局和交互状态 |
| `app.js` | 筛选状态、图表渲染、悬停提示和交互逻辑 |

课程项目可优先使用原生 HTML/CSS/JavaScript 和 SVG，减少依赖；如果项目已有 React、Vue、ECharts、Plotly 或 v0.dev 生成代码，可遵循已有技术栈。

## 六、前端数据准备

前端数据准备脚本应：

1. 从 `data/processed/` 读取明细和特征数据。
2. 从 `data/analysis/` 读取分析结果。
3. 聚合页面需要的趋势、排名、分布、异常、相关性和关键词数据。
4. 保留筛选器所需的年份、日期、周次、地区、类别、指标名称。
5. 输出 `data/dashboard-data.js` 或 `data/dashboard-data.json`。
6. 在控制台打印数据范围和核心记录数，方便验证。

输出摘要示例：

```text
weeks: 2024-W01 至 2026-W20
pathogens: 11
cities: 31
trendRows: 1056
riskRows: 3844
```

## 七、交互设计要求

Dashboard 至少应实现：

| 交互 | 说明 |
|---|---|
| 年份或日期范围筛选 | 控制趋势、表格和图表范围 |
| 股票选择 | 支持按股票代码、股票名称或股票池切换展示对象 |
| 类别筛选 | 如病原体、行业、指标、风险等级 |
| 地区或对象筛选 | 如省市、公司、病种 |
| 指标切换 | 同一图表支持不同指标口径 |
| 缩放或时间窗口 | 支持查看全量或最近部分时间段 |
| 悬停提示 | 显示对象、时间、数值、单位和解释 |
| 重置筛选 | 快速恢复默认视图 |

所有图表应尽量跟随筛选条件变化。若某图表因数据口径限制不能跟随某个筛选器，应在标题、副标题或空状态中说明原因，并切换到合理替代图表。

## 八、图表清晰度规范

图表应满足：

1. 标题说明图表展示什么。
2. 副标题说明当前数据口径或筛选状态。
3. 数值显示单位，如 `%`、例、周、℃、mm。
4. 折线图标注峰值和最新值。
5. 柱状图展示数值标签或参考网格。
6. 散点图说明横轴、纵轴、颜色和点大小含义。
7. 地图或类地图分布图说明颜色代表的风险或强度。
8. 表格字段名称清楚，异常类型用颜色区分。
9. 空状态要解释为什么没有数据，而不是只写“暂无数据”。

如果存在数据口径差异，例如某指标只从某年开始，应在报告和页面中明确说明。

## 九、可视化报告

完成后输出《数据可视化报告》。建议包含：

1. 页面概况。
2. 数据范围。
3. 图表类型与指标。
4. 交互功能。
5. 可视化解释。
6. 数据口径说明。
7. 运行与验证。
8. 截图建议。

报告中应说明：

- 页面入口在哪里。
- 数据文件如何生成。
- 使用了哪些清洗数据和分析结果。
- 每张图表展示什么。
- 哪些图表会随哪些筛选条件变化。
- 哪些结论只是探索性分析，不应解释为因果或业务定论。

## 十、验证可视化结果

至少运行以下检查：

1. 数据准备脚本语法检查。
2. 完整运行数据准备脚本。
3. 检查 `dashboard-data.js` 或 JSON 是否生成。
4. 前端 JS 语法检查。
5. 启动本地 HTTP 服务。
6. 检查 HTML、JS、CSS 和数据文件能正常返回。
7. 打开页面，确认图表不为空、不重叠、不溢出。
8. 测试筛选器、指标切换、缩放、悬停提示和重置。
9. 检查图表是否随筛选条件同步变化。
10. 保存首页截图和至少 2-3 张交互截图。

常用命令：

```bash
python src/dashboard/prepare_dashboard_data.py
python -m http.server 8000
node --check src/dashboard/app.js
node --check data/dashboard-data.js
```

如果本机未配置 `python` 或 `node`，可使用项目环境或 Codex 工作区提供的运行时路径。

## 十一、交付物整理与自动验收

完成可视化阶段后，应整理以下目录或文件。若项目已有命名规范，优先沿用现有命名，但内容必须覆盖这些交付项。

```text
project/
├── src/dashboard/                 # Dashboard 页面代码
├── data/dashboard-data.js          # 前端可视化数据
├── docs/visualization/
│   ├── 数据可视化方案.md
│   ├── 数据可视化报告.md
│   ├── 图表说明.md
│   ├── 运行日志汇总.md
│   ├── 输入输出样例汇总.md
│   └── Agent与Skill复用说明.md
└── screenshots/visualization/
    ├── dashboard-home.png
    ├── stock-select.png
    ├── date-range.png
    ├── zoom.png
    └── hover-tooltip.png
```

自动验收清单：

| 交付项 | 检测方式 |
|---|---|
| Dashboard 代码 | 检查 HTML/CSS/JS 或框架入口文件存在 |
| 3-5 种图表 | 在 `图表说明.md` 中列出图表名称、类型、数据来源、指标含义 |
| 股票选择 | 页面存在股票选择控件，切换后至少一个图表同步更新 |
| 日期范围选择 | 页面存在日期起止或时间窗口控件，图表范围同步更新 |
| 缩放 | 趋势图或时间轴支持局部查看、窗口切换或缩放按钮 |
| 悬停提示 | 图表 hover 展示时间、股票、指标、数值和单位 |
| 页面截图 | `screenshots/visualization/` 至少包含 Dashboard 首页截图 |
| 交互截图 | 至少包含股票选择、日期范围、缩放、悬停提示中的 3 类截图 |
| 运行日志汇总 | 汇总成员 A/B/C 或三名成员的 Agent 记录、运行命令、关键输出 |
| 输入输出样例汇总 | 包含上一阶段输入、前端数据输出、Dashboard 页面输出样例 |
| AI 工具附录 | 包含工作流记录、提示词或对话摘要、人工审核说明 |

运行日志汇总建议按成员整理：

| 成员 | 阶段 | 需要汇总的材料 |
|---|---|---|
| 成员 A | 数据采集 | Agent 使用记录、Skill 文件、采集命令、输入输出样例、运行日志 |
| 成员 B | 数据清洗与分析 | Agent 使用记录、Skill 文件、清洗/分析命令、结果文件、运行日志 |
| 成员 C | 数据可视化 | 本技能工作流、Dashboard 运行命令、页面截图、交互截图、人工审核说明 |

人工审核说明至少写明：

1. 图表是否正确读取成员 B 的数据。
2. 图表数量和类型是否满足要求。
3. 交互控件是否能改变图表结果。
4. 截图是否覆盖页面运行和核心交互。
5. 报告中的结论是否避免把相关性、聚类或异常检测解释成确定因果。

## 十二、课程加分材料建议

如果课程要求说明 AI Agent 和 Skills 使用过程，应补充：

1. 可视化 Agent 工作流目标。
2. 关键提示词或对话摘要。
3. 数据准备脚本运行命令截图。
4. Dashboard 页面运行截图。
5. 筛选、缩放、悬停提示等交互截图。
6. 输入文件样例。
7. 输出文件样例。
8. 人工审核说明。
9. 本 Skill 的 `SKILL.md` 或复用说明。

截图建议至少包含：

- Dashboard 首页。
- 指标切换后的趋势图。
- 地区或对象筛选后的对比图。
- 悬停提示截图。
- 异常检测或预警候选表。
