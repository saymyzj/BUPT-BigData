# 大数据分析数据分析工作流

本技能用于复用一套完整的大数据分析流程。适合在用户已经完成数据清洗并生成 `data/processed/` 后，需要继续完成统计分析、建模分析、结果文件、应用价值分析和报告撰写时使用。

## 一、总体流程

除非用户只要求完成其中某一步，否则按以下顺序推进：

1. 阅读分工指南、数据采集报告、清洗报告和已生成的数据字典。
2. 盘点 `data/processed/` 中可用于分析的数据表和字段。
3. 编写《数据分析方案》。
4. 编写或更新分析脚本。
5. 生成描述性统计结果。
6. 生成时间序列趋势分析结果。
7. 生成相关性矩阵。
8. 生成聚类结果或风险分组。
9. 生成异常检测或早期预警候选结果。
10. 如任务要求，生成舆情关键词或情绪分析结果。
11. 生成分析输出文件的数据字典。
12. 编写《数据分析报告》和《整体应用价值分析》。
13. 运行脚本验证，检查输出文件和报告结构。

不要只在报告中写结论。应同时生成可交付的结构化分析结果文件，方便可视化成员或后续模块复用。

## 二、输入数据盘点

分析前先形成输入数据清单：

| 输入文件 | 数据内容 | 分析用途 |
|---|---|---|
| `data/processed/example_clean.csv` | 清洗后数据 | 描述统计、趋势分析 |
| `data/processed/features.csv` | 特征宽表 | 相关性、聚类、异常检测 |

重点检查：

| 检查项 | 说明 |
|---|---|
| 数据字典 | 是否说明字段含义、类型、单位、缺失处理 |
| 时间字段 | 是否有日、周、月等可排序字段 |
| 数值字段 | 是否能直接计算均值、相关性或聚类 |
| 类别字段 | 是否能作为分组变量 |
| 缺失值 | 是否解释清楚结构性空值和真实缺测 |
| 分析粒度 | 是否明确记录粒度，如城市 × 周、病种 × 月 |

## 三、数据分析方案

在写分析脚本前，先输出《数据分析方案》。方案至少包括：

1. 分析目标。
2. 输入数据。
3. 分析方法设计。
4. 输出文件设计。
5. 脚本设计。
6. 整体应用方向。
7. 阶段性实施计划。

分析任务通常至少覆盖：

| 分析类型 | 目标 |
|---|---|
| 描述性统计 | 总结均值、最大值、最小值、总和、最新值 |
| 时间序列分析 | 分析趋势、变化量、变化率和近期均值 |
| 相关性分析 | 分析不同变量之间的线性关系 |
| 聚类分析 | 对对象进行风险分组或特征分组 |
| 异常检测 | 识别异常高值、异常低值或预警候选事件 |
| 舆情关键词/情绪分析 | 分析文本字段中的关注关键词或情绪倾向 |

## 四、分析代码架构

推荐目录结构：

```text
project/
├── data/
│   ├── processed/
│   └── analysis/
├── src/
│   ├── analysis/
│   │   ├── __init__.py
│   │   └── analyze_cleaned_data.py
│   └── utils/
├── 数据分析方案.md
└── 数据分析报告.md
```

推荐模块划分：

| 模块或函数 | 职责 |
|---|---|
| `read_csv` / `write_csv` | 统一读取和写出分析结果 |
| `to_float` | 将 CSV 字段转换为数值 |
| `generate_descriptive_statistics` | 生成描述统计 |
| `generate_time_series_summary` | 生成时间序列趋势摘要 |
| `generate_correlation_matrix` | 生成相关性矩阵 |
| `generate_cluster_results` | 生成聚类或风险分组结果 |
| `generate_anomaly_results` | 生成异常检测结果 |
| `generate_keyword_sentiment_analysis` | 生成关键词或情绪分析结果 |
| `build_analysis_dictionary_rows` | 生成分析输出字段说明 |
| `build_summary` | 汇总核心结论、应用方向和可行性 |
| `run_analysis` | 串联完整分析流程 |

代码规范要求：

1. 顶部写模块说明，说明分析输入、输出和方法。
2. 每个主要函数写 docstring。
3. 分析方法要和输出文件一一对应。
4. 相关性、聚类、异常检测等结论要保守解释，不直接写成因果关系。
5. 输出字段顺序固定，保证可视化成员稳定读取。
6. 使用第三方库前先检查项目依赖；课程项目可优先使用标准库实现。

## 五、描述性统计

描述统计结果推荐输出：

```text
data/analysis/descriptive_statistics.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `dataset` | 来源数据表 |
| `group_name` | 分组名称 |
| `metric_name` | 指标名称 |
| `observations` | 观测数量 |
| `mean` | 均值 |
| `min` | 最小值 |
| `max` | 最大值 |
| `sum` | 总和 |
| `latest_period` | 最新时期 |
| `latest_value` | 最新值 |

适合分析：

- 病种病例数分布。
- 病原体阳性率分布。
- 指标峰值和最新值。
- 地区或对象之间的差异。

## 六、时间序列趋势分析

时间序列结果推荐输出：

```text
data/analysis/time_series_summary.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `series_name` | 序列名称 |
| `frequency` | 时间粒度 |
| `start_period` | 起始时期 |
| `end_period` | 结束时期 |
| `latest_value` | 最新值 |
| `previous_value` | 上一期值 |
| `change` | 变化量 |
| `change_percent` | 变化率 |
| `recent_4_period_avg` | 最近 4 期均值 |
| `trend_direction` | 趋势方向 |

趋势结论要说明数据频率，例如周度、月度、季度或年度。

## 七、相关性分析

相关性结果推荐输出：

```text
data/analysis/correlation_matrix.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `x_variable` | 自变量或第一变量 |
| `y_variable` | 因变量或第二变量 |
| `sample_size` | 样本量 |
| `pearson_correlation` | Pearson 相关系数 |
| `abs_correlation` | 相关系数绝对值 |
| `strength` | 相关强度 |
| `direction` | 正相关或负相关 |

相关性强度建议：

| 相关系数绝对值 | 解释 |
|---:|---|
| ≥ 0.7 | 强相关 |
| 0.4-0.7 | 中等相关 |
| 0.2-0.4 | 弱相关 |
| < 0.2 | 相关较弱 |

必须提醒：相关性不等于因果关系。若数据存在重复周、重复地区或重复对象，应先按合理粒度聚合后再计算相关性。

## 八、聚类分析

聚类结果推荐输出：

```text
data/analysis/cluster_results.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| 对象标识字段 | 如地区、城市、企业、病种、日期 |
| `cluster_id` | 聚类编号 |
| `risk_level` 或 `cluster_label` | 风险等级或类别标签 |
| `risk_score` | 风险得分或综合得分 |
| 特征字段 | 用于聚类的原始指标 |

聚类前应：

1. 明确聚类对象。
2. 选择数值型特征。
3. 处理缺失值。
4. 对特征做标准化。
5. 根据业务含义给聚类结果命名。

聚类结果不是最终业务判断，应作为风险分组或可视化提示候选。

## 九、异常检测

异常检测结果推荐输出：

```text
data/analysis/anomaly_detection_results.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `series_name` | 序列名称 |
| `period` | 异常时期 |
| `value` | 当前值 |
| `mean` | 序列均值 |
| `stddev` | 序列标准差 |
| `z_score` | 标准化异常分数 |
| `anomaly_type` | 异常高值或异常低值 |

常用规则：

```text
abs(z_score) >= 2  标记为异常
```

异常检测结果应作为预警候选，后续需要人工复核或结合领域知识解释。

## 十、舆情关键词或情绪分析

如果项目没有真实社交媒体或评论数据，不要虚构舆情。可以改做“官方通报文本关键词分析”，并在报告中明确说明不是社交媒体主观情绪。

推荐输出：

```text
data/analysis/keyword_sentiment_analysis.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `source_table` | 来源数据表 |
| `keyword` | 关键词 |
| `category` | 关键词类别 |
| `occurrences` | 出现次数 |
| `document_count` | 覆盖记录数 |
| `attention_label` | 常规监测关注、风险关注、正向、负向等 |
| `explanation` | 结果解释 |

如果确实有评论、新闻、社交媒体文本，可进一步做正负面词典、情绪分类或主题聚类。

## 十一、分析数据字典

分析阶段应生成分析结果字段说明：

```text
data/analysis/analysis_data_dictionary.csv
```

推荐字段：

| 字段 | 含义 |
|---|---|
| `table_name` | 分析输出文件名 |
| `field_name` | 字段名称 |
| `data_type` | 字段类型 |
| `unit` | 字段单位 |
| `description` | 字段含义 |

该数据字典应覆盖所有分析输出文件，包括 CSV 和 JSON 摘要。

## 十二、数据分析报告

分析完成后输出《数据分析报告》。建议包含：

1. 分析概况。
2. 描述性统计结果。
3. 时间序列趋势分析。
4. 相关性分析结果。
5. 聚类风险分组结果。
6. 异常检测结果。
7. 舆情关键词或情绪分析结果。
8. 整体应用方向。
9. 技术可行性、成本效益、市场需求、数据可用性分析。
10. 项目价值。
11. 输出文件清单。

报告中应明确：

- 分析方法如何计算。
- 结果文件在哪里。
- 结论是否有局限。
- 相关性不是因果。
- 聚类和异常检测只是辅助判断。

## 十三、整体应用价值分析

如果用户需要单独交付整体分析，可输出：

```text
整体应用价值分析.md
```

至少覆盖：

| 维度 | 内容 |
|---|---|
| 应用方向 | 至少 2 个创新且可落地的方向 |
| 技术可行性 | 数据、脚本、算法、部署是否可行 |
| 成本效益 | 数据成本、开发成本、运行成本和收益 |
| 市场需求 | 学校、社区、医院、企业、监管等场景需求 |
| 数据可用性 | 数据规模、质量、时间粒度、字段完整性 |
| 项目价值 | 对业务、研究、展示或决策的贡献 |

## 十四、验证分析结果

至少运行以下检查：

1. 脚本语法检查。
2. 完整运行分析脚本。
3. 检查所有输出文件是否生成。
4. 检查分析数据字典是否覆盖所有输出字段。
5. 检查结果行数是否与摘要一致。
6. 检查相关性样本量是否足够。
7. 检查聚类标签是否有业务解释。
8. 检查异常结果是否可解释。

常用命令：

```bash
python -m py_compile src/analysis/analyze_cleaned_data.py
python src/analysis/analyze_cleaned_data.py
```

如果输出 CSV 被 Excel、WPS 或预览程序打开，可能导致写入失败。提醒用户关闭相关文件后再运行。
